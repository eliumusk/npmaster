# 数据泄露

## 定义

训练集和测试集之间**存在信息共享**，导致测试性能被高估。

## 本项目中的三类泄露

### 1. BGC级泄露（最致命）

**场景**：同一个BGC被切成多个窗口（stride=window_size/2），如果随机分train/test，来自同一BGC的窗口会分散到两个集合。

**后果**：测试集相当于在训练集的"邻居样本"上评估，AUROC虚高。

**修复**：train/val/test按BGC source分组，同一BGC的所有窗口只出现在同一个split。见 [[../data/expanded-strep]]。

### 2. 基因组级泄露（负样本）

**场景**：同一个参考基因组的不同非BGC区段，如果随机分train/test，train和test的负样本会共享基因组背景特征。

**后果**：模型记住了特定基因组的特征，测试集AUROC虚高。

**修复**：负样本按基因组（GCF_xxx）分组做split。

### 3. 窗口重叠（stride问题）

**场景**：stride=50%，一个BGC的相邻窗口有50%序列重叠，高度相关。

**后果**：bootstrap CI被低估，测试集的"独立样本数"远小于窗口数。

**修复**：统计分析时必须用BGC级 [[Cluster-Bootstrap]]，不能用窗口级。

## 历史上被抓住的泄露

见 `project_docs/04_数据集问题与解决方案.md`：

| 问题 | 发现者 | 修复 |
|---|---|---|
| 负样本分割没按基因组分组 | Codex review | clean_strep数据集按基因组分组 |
| 窗口级bootstrap CI错误 | 用户指出 | 改用BGC级cluster bootstrap |
| 正负样本物种分布不匹配 | Codex review | 只用Streptomyces |

## 检测方法

```python
# 检查train/test是否有同一BGC
train_bgcs = set(s['source'] for s in train if s['is_bgc']==1)
test_bgcs = set(s['source'] for s in test if s['is_bgc']==1)
overlap = train_bgcs & test_bgcs
assert len(overlap) == 0, f"BGC泄露: {overlap}"

# 检查train/test是否有同一基因组
train_genomes = set(s['source'] for s in train if s['is_bgc']==0)
test_genomes = set(s['source'] for s in test if s['is_bgc']==0)
overlap = train_genomes & test_genomes
assert len(overlap) == 0, f"基因组泄露: {overlap}"
```

## 教训

**"窗口 ≠ 独立样本"**。8192bp滑动窗口(50% stride)导致每个BGC产生多个高度相关窗口，bootstrap必须用cluster级别。

参见 [[Cluster-Bootstrap]]。
