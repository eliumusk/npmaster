# 下一步计划与思考

> 写于2026-04-04，基于首轮GPU实验结果（Evo2 AUROC=0.941 on Streptomyces-only）

## 当前已验证的核心结论

Evo2 7B的DNA embedding（blocks.20层，4096维）在Streptomyces内的BGC检测任务上，显著优于k-mer baseline（+0.048 AUROC），且在无GC/物种偏差的干净数据集上取得。**方向已验证，值得继续投入。**

## 接下来可以做的事（按优先级排序）

### P0：必须做（论文核心）

#### 1. 公平对比BGC-Prophet
**目的**：证明Evo2 > ESM-2，这是论文的核心claim

**Codex review指出**：当前对比是苹果比橙子（基因级 vs DNA窗口级）。需要做两个对照实验：

**实验A：基因级Evo2（公平编码器替换）**
- 保持BGC-Prophet的框架（128个基因窗口 + Transformer encoder + CRF）
- 只把ESM-2替换为Evo2：每个基因的DNA序列 → Evo2 → embedding
- 这样与BGC-Prophet在完全相同的任务和数据上对比
- 工作量：中等（需要从MIBiG GenBank提取每个基因的DNA序列，然后用Evo2编码）

**实验B：在BGC-Prophet的NG测试集上评估**
- 在BGC-Prophet论文使用的9个基因组测试集上评估我们的模型
- 这样结果可以直接与论文表格对比

#### 2. 多属扩展
**目的**：证明方法不局限于Streptomyces

**做法**：
- 给Micromonospora、Amycolatopsis各准备配对数据（我们已下载了这些基因组）
- 需要跑antiSMASH标注这些基因组（约10-15个）
- 评估三种场景：
  - 同属测试（seen genus）
  - 跨属测试（unseen genus）
  - 混合训练后测试

#### 3. 全基因组扫描评估
**目的**：证明模型在真实场景下有用

**做法**：
- 取一个完整基因组，用滑动窗口扫描
- 评估指标：每Mb假阳性数（FP/Mb），而非平衡窗口AUROC
- 与antiSMASH预测结果对比

### P1：应该做（提升论文质量）

#### 4. 消融实验（Ablation Studies）
- **层选择**：比较blocks.10/15/20/25等不同层的效果
- **窗口大小**：8k vs 16k vs 32k
- **Pooling策略**：mean pooling vs max pooling vs attention pooling
- **GC-only baseline**：验证模型不是在学GC含量
- **反向互补一致性**：检查正向和反向互补序列的预测是否一致（Codex建议）

#### 5. 更好的下游网络
当前用的是sklearn的简单分类器，可以尝试：
- **Attention pooling**：不做简单mean，用attention加权
- **CNN头部**：在embedding序列上做1D卷积
- **MIL (Multiple Instance Learning)**：把一个BGC的多个窗口当作一个bag

#### 6. BGC类型分类
当前只做了BGC vs non-BGC的二分类，还没做7类分类（Polyketide/NRP/RiPP等）。
- 正样本中已有类别标签
- 可以用multi-label分类器

### P2：锦上添花

#### 7. 非典型BGC探索
**这是老师最关心的方向**
- 用训练好的模型扫描大量基因组
- 找到模型预测为BGC但antiSMASH没有检测到的区域
- 这些可能是非典型BGC
- 如果有有趣的发现，可以交给生物组做湿实验验证

#### 8. Evo2 40B
如果7B效果好，可以试试40B（需要多卡推理，我们有16张A800足够）

#### 9. 与其他DNA模型对比
- DNABERT-2
- Nucleotide Transformer
- HyenaDNA
看Evo2是否确实是最好的DNA模型选择

## 关于论文写作

基于当前结果，论文的story可以是：

**Title**: "Evo2-BGC: Leveraging DNA foundation models for biosynthetic gene cluster detection"

**核心贡献**：
1. 首次将DNA基础模型（Evo2）应用于BGC检测，绕过了传统方法对基因预测和蛋白质注释的依赖
2. 在无偏差的控制实验中，Evo2 embedding显著优于k-mer baseline和（如果P0.1验证的话）ESM-2 embedding
3. 展示了DNA层面的表示学习在天然产物基因组挖掘中的潜力

**差异化**（与BGC-Prophet的区别）：
- BGC-Prophet在蛋白质层面操作，依赖基因预测 → 我们在DNA层面操作，端到端
- BGC-Prophet用ESM-2（8M参数） → 我们用Evo2（7B参数），模型容量大得多
- BGC-Prophet的训练数据构造依赖antiSMASH → 我们的正样本直接用MIBiG实验验证数据

## 风险与注意事项

1. **不要过度声称泛化性**：当前只在Streptomyces上验证过，不能说"适用于所有细菌"
2. **不要忽略BGC-Prophet的优势**：它在基因级别操作，能精确定位BGC边界和每个基因的角色；我们的窗口级方法不能
3. **注意Evo2的计算成本**：7B模型推理速度~1.2 samples/s，比ESM-2慢得多；如果做大规模基因组筛选需要考虑效率
4. **反向互补问题**：DNA是双链的，同一段序列的正反互补应该给出相同预测；需要验证这一点
