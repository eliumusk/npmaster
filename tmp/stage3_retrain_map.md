# Stage 3 Retrain Map — How To Launch One Route B Retrain

Date: 2026-04-18
Purpose: answer the "how do we launch a Stage 3 data-construction pilot retrain?" question, with file:line evidence.
Status: read-only investigation. No code changed, no commands run.

TL;DR:

- Training entrypoint is **`src/train.py`**, CLI args only, single-GPU PyTorch.
- One Route B retrain on 1 × A800-80GB takes **~35 min wall** (100 epochs × ~21 s/epoch). Confirmed from server log `train_log_route_b_s0.csv` and `train.log`.
- All hard-neg knobs (mine score family, min_score, top_k, loss weight) **already exist as CLI flags**. No code changes needed for a conservative pilot.
- Main missing piece: `meta_arrays.pkl` with a fresh `hard_negative` column — must be regenerated by running `scripts/mine_hard_negatives.py` first. `chunk_index.pkl` and embeddings can be reused as-is for any Stage 3a hardneg sub-axis.
- Distributed training = none. Pilot is pinned to 1 GPU. 8×A800 throughput can only be exploited by running 8 independent trials in parallel, not one distributed trial.

### What one Stage 3a hardneg trial actually rebuilds

Exactly one file: a new `meta_arrays.pkl` with a freshly computed `hard_negative` column. Produced by:

```
scripts/mine_hard_negatives.py --ckpt <seed0 ckpt> \
  --embeddings <mainline embeddings.npy> \
  --meta-arrays <original meta_arrays.pkl> \
  --contig-index <contig_index.pkl> \
  --out-dir <trial-specific dir> \
  --score-name fused --top-k 5000 --min-score 0.95
```

Output under `--out-dir`: `meta_arrays.pkl` (patched), `hardneg_candidates.csv`, `summary.json` (`scripts/mine_hard_negatives.py:207-244`).

Mining time: one full-contig-index forward pass of the Route B model over all embeddings (`scripts/mine_hard_negatives.py:101-120`). ⚠ not timed on record — **inferred, not verified** to be 5–15 min from the ~35-min training wall (mining is ~1 epoch's worth of forward passes without backprop).

## 5. Distributed Training?

**Single-GPU only.**

Evidence:

- `grep -E "DistributedDataParallel|DDP|FSDP|accelerate|torch.distributed|DataParallel" src/` → **no matches**.
- `src/train.py:52` — `device = "cuda" if torch.cuda.is_available() else "cpu"`. Plain single-device.
- Optimizer is vanilla `torch.optim.AdamW` (`src/train.py:136`), no wrapper.
- DataLoader at `src/train.py:71-74` uses `num_workers=4` and has no `DistributedSampler`.
- `train.log` on server shows a single process writing the log; no rank prefixes.

Implication: a Stage 3 pilot is **pinned to 1 GPU**. 8 A800s on node7 → run 8 independent trials concurrently. If we later want wall-clock/trial to drop below 35 min, that requires adding DDP support to `src/train.py` — not in scope for the pilot.

## 6. Reproducibility Gotchas

Things the current checkpoint depends on that make retraining non-trivial:

1. **Warm start from `H_hardneg_r10`** — `configs/mainline.yaml:49-50` and `src/train.py:91-112` load `projector` and `classifier` weights from `H_hardneg_r10/best_H_hardneg_r10.pt`. The context CNN and gate are trained from scratch (init_beta=-4.0). **This means Route B is not a from-scratch train; any Stage 3 retrain must either (a) re-use the same warm-start to stay comparable, or (b) declare a new baseline if it drops it.** The spec's "no confounds" rule (§5) says keep (a).
2. **No frozen Evo2 layers inside `src/train.py`** — embeddings are pre-computed offline (`docs/mainline.md:8`). The projector **is trainable** (`src/train.py:347` lr 1e-4). Good: Route B does not redo Evo2 forward each epoch.
3. **Stage 3 instrumentation is newer than the ckpt** — the current `train_log_route_b_s0.csv` on server has header `epoch,L_bce,val_bgc_auroc,val_region_f1,alpha,lr_proj,lr_ctx,sec` (no `hard_neg_frac`). Current `src/train.py:149` defines `hard_neg_frac` in the header. So the mainline ckpt predates this commit. Any new Stage 3 retrain will produce a wider CSV — downstream analyzers must tolerate this.
4. **Curriculum**: there is a cosine LR schedule with 5-epoch warmup (`src/train.py:139-145`), but no explicit curriculum on hardneg, phylum, or length. Hardneg weight is a constant scalar, not annealed.
5. **Custom loss**: BCEWithLogitsLoss with a dynamic `pos_weight` computed per-class from `n_pos_per_class` clamped at 20.0 (`src/train.py:120-128`). This depends on the `labels` column in `meta_arrays.pkl`, which is **not** changed by hardneg mining (`scripts/mine_hard_negatives.py:44-49` only adds `hard_negative`; it does not touch `labels`). So `pos_weight` will reproduce under hardneg-only Stage 3a. It would change if Stage 3b rebuilds chunks with ambiguous-as-positive.
6. **Gradient clipping at 10.0** (`src/train.py:220`) — hardcoded. Not a gotcha; just note it if comparing to published training recipes.
7. **Val eval every epoch, region-F1 only on multiples of 5** (`src/train.py:235`). Checkpoint-by-best-region-f1 means a trial can look "worse" if it never hits an epoch%5 evaluation at its best moment. Mainline s0 best was at epoch 94. Keep `--epochs 100` to be safe.
8. **Seed handling**: `set_seed(args.seed)` at `src/train.py:51` seeds Python/NumPy/PyTorch. Data order is deterministic within a seed. DataLoader `num_workers=4` may still introduce mild non-determinism across runs — budget ±0.002 region F1 seed noise.
9. **Config dump is source-of-truth for the run** — `src/train.py:153-179` writes a `config_<tag>.json`. This is what reproduces the trial; do NOT rely on `configs/mainline.yaml` alone.

## 7. Minimum Actionable "Launch Stage 3 Pilot" Command

Goal of the pilot: one retrain with fresh hardneg mining from `best_route_b_s0.pt`, conservative settings (top_k=5000, weight=1.0 so we can separate mining effect from weighting effect later; or weight=4.0 per `docs/route-b-hardneg-v1.md:78-80`). **No code changes required.**

I'll give both a "no-change" pilot (Axis C off) and the "recommended first pilot" (Axis C on at weight=4.0 per existing hardneg-v1 doc).

### Paths (from `configs/mainline.yaml:17-24`, verified on node7)

```
EMB=/data/muskliu/npmaster/data/embeddings/edge_padding/embeddings_merged.npy
PROJ=/data/muskliu/npmaster/data/phase3/route_a/projections_256.npy
META_IN=/data/muskliu/npmaster/data/phase3/route_a/meta_arrays.pkl
CONTIG=/data/muskliu/npmaster/data/phase3/route_a/contig_index.pkl
CHUNK=/data/muskliu/npmaster/data/phase3/route_b/chunk_index.pkl
BGC_CSV=/data/muskliu/npmaster/data/bgc_annotations.csv
MAINLINE_WARMSTART=/data/muskliu/npmaster/data/stage3_results/H_hardneg_r10/best_H_hardneg_r10.pt
SEED0_CKPT=/data/muskliu/npmaster/data/phase3/route_b/best_route_b_s0.pt
TRIAL_DIR=/data/muskliu/npmaster/data/stage3_results/stage3a_pilot_w4_k5000_s0
```

### Prereq step — mine hardnegs (runs on 1 GPU, ~10 min ⚠ inferred)

```bash
mkdir -p "$TRIAL_DIR/mining"
python scripts/mine_hard_negatives.py \
  --ckpt "$SEED0_CKPT" \
  --embeddings "$EMB" \
  --meta-arrays "$META_IN" \
  --contig-index "$CONTIG" \
  --out-dir "$TRIAL_DIR/mining" \
  --score-name fused \
  --top-k 5000 \
  --min-score 0.95 \
  --device cuda
```

Verify before training: `jq . "$TRIAL_DIR/mining/summary.json"` should report `n_hard_negative: 5000` (or close; may be less if fewer than 5000 negatives score ≥ 0.95).

### Training step (1 × A800, ~35–40 min wall)

Pilot A (matches mainline exactly except `meta_arrays` now has fresh hardneg flags; weight stays at 1.0 so hardneg loss-side is a no-op — this isolates the pure-mining effect):

```bash
mkdir -p "$TRIAL_DIR/train"
python src/train.py \
  --embeddings "$EMB" \
  --projections "$PROJ" \
  --chunk-index "$CHUNK" \
  --meta-arrays "$TRIAL_DIR/mining/meta_arrays.pkl" \
  --contig-index "$CONTIG" \
  --bgc-csv "$BGC_CSV" \
  --ckpt "$MAINLINE_WARMSTART" \
  --out-dir "$TRIAL_DIR/train" \
  --seed 0 \
  --tag stage3a_pilot_w1_k5000_s0 \
  --batch-size 64 \
  --epochs 100 \
  --lr-proj 1e-4 --lr-context 1e-3 --lr-classifier 1e-3 \
  --wd 1e-4 --warmup-epochs 5 \
  --proj-hidden 2048 --proj-out 256 \
  --proj-dropout 0.3 --cnn-dropout 0.1 --init-beta -4.0 \
  --hard-neg-weight 1.0
```

Pilot B (recommended first pilot per `docs/route-b-hardneg-v1.md:77-85` — same command, change weight to 4.0 and update tag):

```bash
  --hard-neg-weight 4.0
  --tag stage3a_pilot_w4_k5000_s0
```

Everything else stays identical to mainline (`configs/mainline.yaml`). No other flags need to change.

## Verdict: can we safely launch a pilot tonight?

**YES, estimated ~1 hour wall per trial** (10 min mine + 35–40 min train + 5 min eval), on 1 × A800-80GB node7, zero code changes, reusing the frozen mainline embeddings and chunk index and only regenerating `meta_arrays.pkl` via the existing `scripts/mine_hard_negatives.py`. The warm-start checkpoint and all input artifacts are already on node7's GPFS at the paths in `configs/mainline.yaml`. Risks to watch: **(R1) 9-genome precision-gap hypothesis** — per `docs/next-phase.md` the gap may be benchmark-GT narrowness, not trainable false-positives, in which case hardneg weighting could regress recall without moving precision; sample 20 fresh hardneg picks before burning more than 1 trial. **(R2) eval contract on `scripts/evaluate_nine_genome.py`** — the exact flag list was not verified in this pass; run with `--help` first, and confirm the pilot uses `--operating-point val_frozen_fused` and the dev split from `configs/splits/nine_genome_dev_lockbox_v1.json` so results are comparable to the current operating-point table.
