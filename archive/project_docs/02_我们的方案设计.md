# 我们的方案：用 Evo2 替代 ESM-2 做 BGC 预测

## 一、核心思路

BGC-Prophet的pipeline：
```
DNA → 基因预测 → 蛋白序列 → ESM-2嵌入(蛋白质层面) → Transformer → BGC预测
```

我们的pipeline：
```
DNA → 直接用 Evo2 嵌入(DNA层面) → 分类器 → BGC预测
```

## 二、为什么 Evo2 可能更好

### 2.1 信息更完整
- ESM-2 只看蛋白质编码区（基因），丢失了：
  - 基因间区（可能有调控信息）
  - 启动子、操纵子结构
  - 非编码RNA
  - GC含量变化等DNA层面的信号
- Evo2 直接看DNA，所有信息都保留

### 2.2 不依赖基因预测
- BGC-Prophet需要先做基因预测（用Prodigal等工具），预测错误会级联传播
- Evo2直接处理原始DNA，没有这个问题

### 2.3 对非典型BGC更友好
- ESM-2依赖蛋白质的序列模式 → 非典型蛋白质难识别
- Evo2从DNA层面学到的模式更底层、更通用

## 三、技术方案详细设计

### 方案A：基因级别（与BGC-Prophet可比）

这个方案保持跟BGC-Prophet相同的任务定义（基因级别预测），只是替换编码器。

```
1. 从基因组中预测基因（Prodigal）
2. 取每个基因的DNA序列（不是蛋白质序列！）
3. 每个基因的DNA → Evo2 → 取平均embedding → D维向量（4096维）
4. 128个基因 → (128, 4096)
5. → Transformer Encoder → 检测 + 分类
```

**优点**：跟BGC-Prophet完全对标，便于写论文比较
**缺点**：仍然依赖基因预测，没有完全发挥Evo2的优势

### 方案B：DNA片段级别（更充分利用Evo2）

这个方案直接在DNA序列上操作，不做基因预测。

```
1. 将基因组DNA切成固定长度的窗口（如8192bp或更长）
2. 每个窗口 → Evo2 → 每个碱基位置的embedding → (8192, 4096)
3. 对embedding做pooling/降维 → 固定维度的表示
4. → 分类器 → 判断这个窗口是否包含BGC + 类别
```

**优点**：完全端到端，不依赖任何预处理
**缺点**：需要自己定义窗口策略，不容易精确定位BGC边界

### 方案C：混合方案（推荐）

结合A和B的优点。

```
第一阶段（粗筛）：用方案B在DNA层面快速扫描，找到可能包含BGC的区域
第二阶段（精定位）：对候选区域做基因预测，再用方案A做精确的基因级别标注
```

## 四、建议的实验路线

### 阶段1：最小可行性验证（1周）
- 用方案A，只替换编码器
- 使用BGC-Prophet的现有训练数据（直接复用他们的正负样本划分）
- 唯一的改动：把每个基因的蛋白序列改成DNA序列，用Evo2编码
- 对比AUROC是否接近或超过BGC-Prophet

### 阶段2：DNA层面实验（2周）
- 用方案B，直接在DNA上做
- 需要重新构造数据集（从MIBiG获取DNA序列而非蛋白质序列）
- 测试不同窗口大小的效果

### 阶段3：完整系统（2-3周）
- 方案C混合系统
- 大规模评估
- 与antiSMASH和BGC-Prophet做全面对比

## 五、数据构建方案

### 5.1 从BGC-Prophet数据出发（阶段1）

BGC-Prophet已经做好了正负样本划分，每个样本是128个基因ID的列表。
- 我们需要的额外工作：找到每个基因ID对应的DNA序列
- 来源：MIBiG的GenBank文件（包含完整DNA序列和基因注释）+ GTDB参考基因组

### 5.2 从头构建DNA数据集（阶段2）

```
正样本：
  MIBiG GenBank文件 → 提取BGC区域的完整DNA序列
  两侧各加5kb flanking序列
  
负样本：
  参考基因组 → 去掉已知BGC区域 → 随机截取等长DNA片段
```

## 六、需要注意的陷阱

1. **数据泄露**：确保训练集和测试集没有来自同一个基因组的样本
2. **类别不平衡**：Alkaloid只有318个样本 vs Polyketide有5135个，需要用focal loss或过采样
3. **序列长度差异**：BGC从几kb到>100kb不等，固定窗口会切断大BGC
4. **负样本质量**：负样本必须与正样本相似度适中（太简单模型学不到东西，太难模型学不会）
5. **Evo2显存**：7B模型处理长序列(>10kb)时显存需求大，需要做好batch管理
